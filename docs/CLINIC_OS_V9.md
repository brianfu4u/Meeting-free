## 一、V9 的本质跃迁

V8 解决了"决策如何留存与验证"，V9 解决的是"**决策从何而来**"。

V9 规定：系统中没有任何一条业务状态变更可以"凭空发生"。所有状态流转必须由三大锚点之一触发，经核心决策引擎校验后，才能落到看板与复盘层。~~游离态数据在 V9 中被视为违宪，直接丢弃并告警。~~

## 二、三大触发锚点（详细逻辑定义）

### 锚点 A1 · 交叉验证触发锚点（Cross-Verification Anchor）

**定位**：系统的真相引擎，负责消除流程盲点与数据冲突。  
**触发主体**：系统自动比对 + 人工确认（双轨）。  
**触发条件**：当两路独立数据源对同一事实的描述出现矛盾时，强制触发。

**逻辑定义**：
- 输入：两个独立信号源对同一实体的状态断言。
- 校验规则：
  - 若两路一致 → 视为已验证，状态收敛，不触发告警。
  - 若两路不一致 → 标记为 `VerificationConflict`，锁定该实体状态，向店长端推送强制裁决任务。
- 闭环要求：冲突未裁决前，该实体不可进入下一状态节点；复盘看板将其计为"闭环缺失"，直接扣减区域健康分。

**典型场景**：
- 看板拥堵指数显示"检查区 3 号位满载"，但扫码记录显示"3 号位 15 分钟无患者进入" → 触发交叉验证冲突，要求店长核实是数据漏扫还是设备误报。
- 收费结算标记"已完成"，但患者路径扫码仍停留在"配镜交付" → 触发冲突，拦截结算闭环。

**实体字段约定**：
- 每条交叉验证事件必须记录：`source_a`、`source_b`、`conflict_type`、`verdict`（待裁决/已裁决）、`verdict_by`、`verdict_time`。

---

### 锚点 A2 · 患者路径扫码触发锚点（Flow-Tracking Anchor）

**定位**：系统的物理位移感知器，将患者流动转化为可审计的数据流。  
**触发主体**：医生 / 护士 / 接待人员通过终端扫描患者病历卡二维码。  
**触发条件**：扫码动作发生即触发，无延迟。

**逻辑定义**：
- 每位患者挂号时分配全局唯一 `patient_id`，并生成一张物理病历码（贴纸），全程随身。
- 扫码 payload 协议（强制字段）：
  ```json
  {
    "patient_id": "SH001-P9988",
    "clinic_id": "SH001",
    "scan_point": "reception|examination|treatment|fitting|checkout",
    "operator_id": "STAFF-007",
    "timestamp": "2026-07-06T09:15:22+08:00"
  }
  ```
- 状态机校验：扫码动作必须符合预定义的状态机跳转顺序。逆序或跳序扫码视为"流程违例"，触发 A1 交叉验证。
- 因果链绑定：每一次扫码自动生成一条 `FlowEvent`，并计算与上一节点的时间差，作为该环节"停留时长"证据。

**闭环要求**：
- 扫码后 0.5 秒内，终端必须给出视觉反馈（绿灯成功 / 红灯违例）。
- 看板对应区域计数实时联动（上一区域 -1，当前区域 +1）。
- 若某节点扫码后超过"预设标准时长"仍未出现下一节点扫码，触发 A3 滞留预警。

**典型场景**：
- 患者在接待台扫码入队 → 接待区排队 +1。
- 视光师接诊时扫码 → 接待区 -1，检查区 +1，同时启动"检查时长计时器"。
- 检查超 25 分钟未扫码出区 → 触发 A3 滞留预警。

---

### 锚点 A3 · 系统逻辑预警触发锚点（Systemic / Logic Trigger）

**定位**：系统的智能中枢，变"被动处理"为"主动治理"。  
**触发主体**：核心决策引擎基于时间规律与态势推断自动触发，无需人工介入。  
**触发条件**：满足以下任一规则即触发。

**逻辑定义（三类触发规则）**：

1. **时间触发（Time-based）**
   - 定时巡检：每 5 分钟扫描全院状态。
   - 班次节点：班次结束前 30 分钟强制清理未闭环事项。
   - 高峰预判：基于历史规律，在预测高峰前 10 分钟发出预防性调度建议。

2. **阈值触发（Threshold-based）**
   - 任一区域指标越过红线（如排队 > 10、等待 > 20 分钟、库存 < 安全线）。
   - 闭环率低于 80% 时，自动升级未处理事项优先级。

3. **态势推断触发（Pattern-based）**
   - 连续 3 个同期班次出现同类拥堵 → 系统判定为"结构性问题"，不再发临时告警，而是生成"经营改善建议"进入复盘看板。
   - 某操作员扫码响应时长连续异常 → 触发人员效能预警。

**闭环要求**：
- A3 触发的预警必须附带"建议处置方案"，供店长一键采纳或驳回。
- 被驳回的预警不消失，而是进入"待观察"队列，30 分钟后若态势未改善则再次触发并升级。

**典型场景**：
- 周六 09:50，系统根据历史数据预判 10:00 检查区将拥堵，自动建议"提前调入视光师 X 支援"。
- 库存跌破安全线，系统自动生成补货建议并推送给后勤负责人。

## 三、三大锚点的协作关系

三大锚点并非孤立，而是构成一张"触发网"：

| 协作关系 | 说明 |
| :--- | :--- |
| A2 → A1 | 扫码产生的状态跳转若与看板态势矛盾，自动激活交叉验证。 |
| A2 → A3 | 扫码超时未发生，由 A3 发出滞留预警。 |
| A3 → A1 | 系统预警发现的数据异常，需 A1 交叉验证确认是否为真异常。 |
| A1 → A3 | 交叉验证反复触发同类冲突，升级为 A3 的结构性问题研判。 |

**核心原则**：任何一个锚点触发后，核心引擎必须记录"触发源标签"（`triggered_by: A1|A2|A3`），确保复盘时可追溯每条决策的起源。

## 四、状态机强制收敛（V9 新增）

患者就诊状态在 V9 中不再是自由文本，而是严格的状态机：

```
[挂号入队] → [接待完成] → [检查中] → [检查完成] → [配镜/治疗] → [结算出店]
     ↑            ↑           ↑           ↑             ↑            ↑
   A2 触发     A2 触发     A2 触发     A2 触发       A2 触发      A2 触发
                          (A3 监控时长)            (A1 校验与结算一致)
```

- 每个节点有"预设标准时长"，超时由 A3 预警。
- 跳跃式跳转（如从"挂号"直接到"结算"）视为违例，触发 A1 冲突。
- 状态一旦收敛到"结算出店"，该 `PatientSession` 归档，进入复盘数据池。

## 五、闭环治理原则（V9 最高执行律）

1. **无锚点不触发**：任何状态变更必须有 A1/A2/A3 之一作为触发源，否则违宪。
2. **无闭环不留存**：被触发的异常必须走完"发现 → 决策 → 执行 → 留存"四步，未走完的在复盘中标记为"永久缺失记录"。
3. **无证据不裁决**：店长决策必须基于锚点提供的数据证据，决策与证据一并存档。
4. **无追溯不结案**：每条复盘记录必须可追溯到具体锚点触发事件。
